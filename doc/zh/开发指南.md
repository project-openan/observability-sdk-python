# OpenAN Python 可观测性 SDK：开发指南

[English](../en/development-guide.md) · [API 参考](API参考.md)

本文介绍 SDK 开发、信号定义和贡献约定。

## 1. 环境与安装

- Python 3.10 或更高版本
- Git
- 导出观测数据时需要可访问的 OpenTelemetry Collector

在仓库根目录以可编辑模式安装：

```powershell
python -m pip install -e .
```

SDK 使用 OpenTelemetry Python 提供信号 API 和 OTLP Exporter，支持 OTLP/gRPC 与 OTLP/HTTP protobuf。

## 2. 目录结构

| 路径 | 用途 |
|---|---|
| `src/openan_observability_sdk/config.py` | 公开配置和环境变量解析 |
| `src/openan_observability_sdk/definitions.py` | 加载和索引信号 YAML |
| `src/openan_observability_sdk/observability.py` | 校验并记录 Trace、Metric 和 Log |
| `src/openan_observability_sdk/sdk.py` | 创建和管理 OpenTelemetry Provider 与 OTLP Exporter |
| `src/openan_observability_sdk/config/` | 随包发布的 A2A-T、Workflow 和 Agent 定义 |
| `examples/` | Workflow/Agent 与 HTTP 上下文传播示例 |
| `doc/` | 中英文 API 参考和开发指南 |

公开 API 从 `openan_observability_sdk` 导出。以下划线开头的名称属于实现细节。

## 3. 初始化与关闭

通常每个应用进程创建一个 SDK，并在应用退出时关闭。短时进程退出前调用 `flush()`，以便队列中的观测数据完成导出。

```python
from openan_observability_sdk import ObservabilitySdk, SdkConfig

with ObservabilitySdk.start(SdkConfig(service_name="diagnosis-agent")) as sdk:
    observe = sdk.observe()
    # 记录应用信号。
    if not sdk.flush(timeout=10):
        raise RuntimeError("OTLP flush failed or timed out")
```

运行时调用 `set_enabled(False)` 可停止创建新的 SDK 信号。关闭开关前创建的 Span 仍可结束并导出。

## 4. 记录信号

### 4.1 A2A / A2A-T

A2A 请求 Span 使用 `CLIENT` 或 `SERVER`。A2A-T 消息 Span 和消息 Log 需要 `extension.name`，此值决定其余可用属性：

A2A Trace 名称与 Java SDK 的 JSON-RPC 方法名一致，例如 `SendMessage`、`SendStreamingMessage` 和 `GetTask`。`GetExtendedAgentCard` 与 `SendPushNotification` 仅支持 Client；`SendStreamingMessage-negotiation` 仅支持 Server。流事件和流错误 Span 会将传入 parent 或当前 Span 保留为 Span Link。

| `extension.name` | 属性示例 |
|---|---|
| `task-t` | `task.type`、`task.object` |
| `negotiation-t` | `negotiation.id`、`negotiation.round`、`negotiation.result`、`negotiation.performative` |
| `notification-t` | `notification.topic`、`push.notification.url` |
| `authorization-t` | `authorization.stage`、`authorization.policy.operation.type` |

Task-T Span、消息 Log、`task.duration` 和 `task.count` 都要求非空的 `task.type`。

### 4.2 Workflow

Workflow Span 使用 `a2at.workflow`；Step Span 使用 `workflow.yaml` 中声明的名称。必填属性和 Metric 维度均由该 YAML 文件定义。

### 4.3 Agent

Agent Substep Span 使用 `agent.yaml` 中声明的名称。`agent.skills` 是由非空字符串组成的列表。Token 用量 Metric 要求 Agent 名称、模型和 Token 类型维度。

## 5. Trace 上下文、异常和运行时更新

调用外部服务前使用 `TraceContextPropagation.inject`，接收请求后创建 Span 前使用 `extract_to_current`。嵌套任务需要继承当前 Span 时，使用 `with span.make_current():`。

调用 `span.error(exception)` 会记录异常并将 Span 状态设为错误。异常离开 `ObservationSpan` 上下文管理器时也会自动标记失败。

`update_exporters(config)` 会先刷新已有数据，再替换 Exporter。已有 Provider 的服务名、Metric 导出间隔以及 Span/Log 批处理参数不能更改；要修改这些参数请创建新 SDK 实例。

`BatchConfig.export_timeout` 为 API 一致性而保留，但 OpenTelemetry Python 的批处理器当前不会将其传给 Exporter。实际 OTLP Exporter 超时通过 `SdkConfig.export_timeout` 设置。

## 6. 信号定义与兼容性

SDK 随包发布三份 YAML 定义：

| 文件 | 覆盖范围 |
|---|---|
| `src/openan_observability_sdk/config/a2at.yaml` | A2A 和四类 A2A-T 扩展 |
| `src/openan_observability_sdk/config/workflow.yaml` | Workflow 和 Step |
| `src/openan_observability_sdk/config/agent.yaml` | Agent、Substep 和 Token 用量 |

每个文件声明版本、属性及其 OpenTelemetry 名称、Trace/Log 允许列表、必填字段、Metric 和 Metric 维度。更新信号定义时：

1. 与 Java SDK 中的定义保持一致。
2. 递增对应 YAML 文件的版本。
3. 更新相关示例和中英文 API 参考、开发指南。
4. 移除或收紧已发布的信号、属性、类型、必填字段或 Metric 维度时，按破坏性变更处理。

当前 A2A 配置版本为 `1.0.0`。

## 7. Commit 与 Pull Request

- 使用 Conventional Commit，例如 `feat(sdk): add exporter option` 或 `fix(validation): reject invalid metric dimension`。
- 每个 commit 都使用 `git commit -s` 添加 DCO sign-off。
- 从个人 fork 创建 Pull Request，目标仓库为 `project-openan/observability-sdk-python`。
- PR 说明主要变更、兼容性影响和验证结果。
